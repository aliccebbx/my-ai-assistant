ответа assistant в истории модель не знает, что это за «второй шаг»:

Задание 16. Правило сокращения истории

Введена переменная max_pairs = 3. Алгоритм сокращения своими словами:
1) сохранить первое сообщение списка — system (messages[0]);
2) выбрать срезом messages[-2 * max_pairs:] последние шесть обычных
   сообщений — три последние пары user + assistant;
3) объединить system и срез в новый список:
   messages = [messages[0]] + messages[-2 * max_pairs:].
Итоговая длина не превышает 1 + 2 * max_pairs = 7. Сокращение
выполняется после добавления ответа помощника, перед выводом длины.

Проверка в history_demo.py без API: создан список из 9 сообщений
(system + четыре пары user/assistant, ответы помечены «Тестовый ответ
без API»), модель не вызывалась. До сокращения — 9 сообщений.
После выполнения алгоритма — 7: первая роль system, самый первый обмен
вытеснен, остались system и три последние пары.

Проверка в main.py: четыре обмена подряд дали длины 3, 5, 7 и снова 7 —
история не выросла до 9, самый старый обмен вытеснился. Ответы модели
показывают, что контекст сохраняется: на вопрос «расскажи подробнее
про первый шаг» помощник опирался на предыдущий ответ. После команды
«очистить» длина стала 1 (только system).

Вывод: срез [-k:] выбирает последние k элементов, system сохранён
первым элементом объединённого списка, старые обмены вытесняются
первыми. История не растёт бесконечно, запросы остаются ограниченными.

программы, chat_history.txt хранит текст для просмотра и проверки.
Наличие файла само по себе не даёт модели доступ к его содержимому.

Задание 18. Запись завершённых обменов в журнал

После каждого успешного ответа в chat_history.txt дозаписываются
реплика пользователя со строкой «user: <текст>» и ответ помощника
со строкой «assistant: <текст>». Между обменами оставлена пустая
строка. Запись ведётся через with open(..., "a", encoding="utf-8"):
режим a дописывает в конец файла и не стирает предыдущие записи,
кодировка UTF-8 сохраняет русский текст.

В журнал записывается обычный текст из переменных text и answer,
а не весь объект response. Команда «очистить» добавляет в журнал
строку «--- история очищена ---»; предыдущие записи при этом не
удаляются — журнал предназначен для просмотра и проверки, а messages
в памяти начинает новый разговор с system.

Проверка: после двух обменов («сколько времени займет убрать кухню»,
«как помыть пол»), очистки и нового обмена («сколько стоит уборка
дома») файл содержит подписанные реплики в порядке следования, пустые
строки между обменами, читаемый русский текст; записи до очистки
сохранены.

Задание 19. Границы разговоров в журнале

При каждом запуске программы один раз перед циклом в chat_history.txt
дописывается строка «Новый запуск» — блок стоит вне цикла, поэтому
выполняется единожды за запуск. При команде «очистить» в журнал
дописывается строка «История текущего диалога очищена». Предыдущие
записи не удаляются — используется режим a.

Команды не уходят модели и не становятся user-сообщениями: «очистить»
и «выход» обрабатываются до добавления в messages. В журнал попадает
только метка очистки. Даты и время не добавлялись.

Проверка: после двух запусков с обменами и очисткой журнал содержит
метку «Новый запуск» в начале каждого запуска, строку «История
текущего диалога очищена» на месте команды «очистить» и все
предыдущие записи.

Задание 20. Два хранилища

Выполнено два обмена, затем очистка истории, затем ещё один обмен и
выход. В chat_history.txt сохранились все три обмена по порядку:
два до очистки, строка «История текущего диалога очищена», один после.
Ограничение контекста не обрезало журнал: файл хранит весь текст, а
messages — только текущий контекст.

Сравнение после очистки и одного обмена: в messages три элемента
(system и новая пара user/assistant), в файле — текст всех трёх
обменов запуска. Модель не помнит факты первых двух обменов — это
ожидаемое поведение: журнал для просмотра и проверки, восстановление
контекста из файла не реализуется.

Проверка нового запуска: при повторном запуске до первого вопроса
в messages находится только system (длина 1). В журнал добавилась
новая метка «Новый запуск», прежний текст сохранился.

Счётчик успешных обменов: заведена переменная exchange_count, она
увеличивается на единицу после каждого полученного ответа assistant.
Команды «очистить», «история», «выход» и пустые строки счётчик не
изменяют. Очистка контекста не сбрасывает счётчик за текущий запуск.
При выходе программа выводит число успешных обменов: 3 после прогона
с двумя обменами, очисткой и одним обменом; 0 после нового запуска
без обменов.
