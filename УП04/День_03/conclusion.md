# Техническое заключение

## 1. Сведения о проекте

- **Название:** ИИ-помощник по уборке и домашним делам.
- **Назначение:** помощь пользователю в планировании уборки и организации быта.
- **Репозиторий:** https://github.com/aliccebbx/my-ai-assistant
- **Дата анализа исходников:** 19.11.2026.

## 2. Результаты инвентаризации

В проекте обнаружены две копии файлов запуска и системного промпта. Основная технология — внешняя модель GigaChat-2, подключаемая через библиотеку `gigachat`. Для загрузки настроек используется `python-dotenv`. В коде также применяется стандартный модуль `os` и CA-сертификат.

В расширенной копии обнаружены файлы сохранения последнего запроса и ответа, а также журнал диалога. Версии Python и сторонних библиотек не установлены. Файл `requirements.txt` и README в просмотренной структуре отсутствуют.

## 3. Диагностика

По файлу `tests.txt` есть записи о семи прежних сценариях. Это исторические результаты, а не подтверждение запуска текущей версии.

Для пяти проверок, рассмотренных в этом аудите:
- 1 запуск программы — не выполнен на локальном компьютере;
- 2 сценария имеют исторические записи ответов, но не перепроверены запуском;
- 1 проверка пустого ввода — выявлено несоответствие в короткой версии;
- 1 дополнительный сценарий — выявлен небезопасный совет в историческом ответе.

Фактическое подключение к GigaChat API не проверено.

## 4. Документация

Созданы документы:
- `inventory.md` — инвентаризация компонентов и файлов;
- `dependencies.md` — анализ зависимостей;
- `documentation_audit.md` — аудит документации;
- `test_results.md` — результаты анализа тестов;
- `conclusion.md` — настоящее заключение.

README и requirements.txt в проекте пока отсутствуют. Команды запуска и установки не подтверждены локальным выполнением.

## 5. Риски

| Риск | Возможное последствие | Действие техника |
|---|---|---|
| Вероятная опечатка `credenticals` в вызове GigaChat | Ошибка при создании клиента | Сверить параметр с установленной версией SDK и проверить подключение |
| Нет проверки пустого ввода в короткой версии | Пустой запрос может уйти в API | Добавить проверку до формирования запроса |
| Не определена основная копия проекта | Изменения могут вноситься не в ту версию | Выбрать актуальную версию и описать структуру |
| Нет requirements.txt и README | Сложно повторить установку и запуск | Создать документы после проверки среды |
| В репозитории хранятся журналы запросов и ответов | Возможна публикация личной информации | Проверить содержимое и исключить приватные данные |
| Нет подтверждённого .gitignore | Риск случайно загрузить .env и виртуальное окружение | Добавить правила исключения и проверить Git |
| Небезопасная рекомендация в одном из тестов | Риск травмы пользователя | Запретить советы вставать на стул или высовываться из окна |

## 6. Итоговый статус

**Готов с ограничениями — только как результат инвентаризации и документального анализа. Работоспособность программы не подтверждена.**

Обоснование: состав проекта и основные связи файлов установлены по репозиторию. При этом локальный запуск, версии зависимостей и подключение к внешнему API не проверены. Также обнаружены расхождения между системным промптом и логикой короткого файла запуска, а в одном тестовом ответе — небезопасный совет.

## 7. Три рекомендации по сопровождению

1. Выбрать одну актуальную версию приложения, устранить проверенные ошибки ввода и подключения, затем выполнить тестовый запуск.
2. Зафиксировать версии зависимостей, добавить `requirements.txt`, `.gitignore` и README с реально проверенными командами.
3. Проверить сохранённые запросы и ответы на персональные данные, а также улучшить промпт и тесты по безопасным бытовым рекомендациям.
